## المرحلة 1 — جارية
1. إثبات الفرع ونظافة البداية وحصر التطبيقات والصفحات والمخططات: تم حصر أولي قابل للتكرار.
2. قراءة مصادر الترحيل والتكلفة والضرائب والإقفال والصلاحيات والتقارير: قراءة موجهة جارية، لا اعتماد نهائي.
3. تجهيز الاعتماديات وتنفيذ فحوص تقنية آمنة منفصلة عن عمليات المستخدم.

## بوابة الأمان قبل أي مستند
- قاعدة جديدة محلية باسم audit_2026؛ لا استعادة بيانات عميل ولا اتصال بقاعدة خارجية.
- مستخدم تطبيق محدود منفصل؛ معرف منشأة اختبار وبيانات موسومة AUDIT-TEST-2026.
- البريد console، الدفع الخارجي والتكاملات الضريبية وwebhooks والتصديرات التلقائية معطلة؛ فحص إعدادات كل مستأجر والعامل قبل الإقلاع.
- التحقق من قاعدة خالية ثم تطبيق الهجرات المحلية ومراجعة seed قبل استخدامه؛ seed يحتوي بيانات تجريبية وليس بيانات عملية التدقيق.
- لا تكفي NODE_ENV=test لإثبات العزل. لا يجوز حفظ المستندات قبل إنجاز هذه البوابة والتصوير.

## المراحل التالية
بيانات أساسية ← شراء واستلام وسداد ← بيع وتحصيل ومردود ← خزينة ومصروف وقيود ← تقارير ومطابقات ← ضوابط وتزامن وإعادة طلب ← إعادة اختبار وملخص. لكل سيناريو توقع مستقل قبل التنفيذ. عند خلل مالي خطير توقف الدورة المتأثرة ولا تسوّ أرصدتها لإخفاء الفرق.

## بروتوكول الأدلة الإلزامي
افتح الشاشة الفعلية، املأ المدخلات، التقط PNG قبل الحفظ، تحقق من وجود الملف وسلامته ثم احفظ؛ سجل UTC والشاشة وID ومرجع المستند المحلي ثم صورة النتيجة وSQL/JSON للآثار والتقرير. لا يُستبدل التصوير باستدعاء API. الاختبارات التقنية القائمة التي تنشئ سجلات على قواعدها المؤقتة تصنف تقنية لا سيناريوهات تشغيل مصورة.

## المخرجات والحالة
السجلات التسعة المطلوبة أنشئت قبل عمليات المستخدم. لم يبدأ إصلاح منطق مالي أو إضافة حزم وظيفية. ملخص المرحلة في TEST_RESULTS، والخطوات المعلقة ليست نتائج ناجحة.


## تقدم الجولة الثانية وحد التوقف
- بوابة تشغيل staff المحلية: نجحت لقاعدة معزولة، ومتصفح حقيقي وصور وfixture معلن. لا إعلان جاهزية لبقية التطبيقات.
- البيانات الأساسية:8 عمليات حفظ ناجحة موثقة، والبحث/الحذف/التعطيل لم تستكمل لكل نوع.
- الدورة المالية: E2E-CREDIT-001 بدأت بشراء آجل ثم بيع آجل؛ **فشلت المطابقة الشاملة**. لا تحصيل أو سداد أو مصروف أو قيد تصحيحي أو مردود بعد اكتشافACC-002/003.
- النقدية موقوفة منذACC-001؛ بقية الكتابات المالية موقوفة بعد الذمم/الربح. قراءة التقارير والصلاحيات تستمر بأمان.
- خطة تالية: استكمال الفحص القرائي لكل التطبيقات والشاشات وجرد النوافذ، ثم الموافقة على قواعد إصلاح مصدر الذمم/تكلفة الرأس/قائمة الدخل/افتتاحياتcache. لا يكفي تعديل تقرير يخفي الفرق.
- قبل استئناف أي كتابة: يثبت إصلاح/حسم العيوب المؤثرة باختبارات منفصلة على قاعدة جديدة وبصور قبل الحفظ، وتعاد الدورة الحالية حرفياً. لا حذف مستندات الإخفاق أو تعديلها لتزيين النتائج.

## الجولة الثالثة — بدأت قبل أي تنفيذ جديد
تستمر وقفة الكتابة المالية في قاعدة المتصفح. أضيفت حزمة قبول تقنية اختيارية في apps/api/test/accounting-audit-regressions.audit.ts وإعداد مستقل، لإعادة إنتاج العيوب على قاعدة PostgreSQL محلية جديدة ذات اسم erp_test_* حصراً، مع رفض أي قاعدة أخرى. تختبر القواعد الصحيحة وتبقى حمراء عند العيب؛ لا `.fails` ولا تخطي ولا تغيير للتوقع كي يمر الخلل. إعدادها منفصل عن الحزمة الافتراضية حتى لا تُدرج حالات القبول الحمراء دون إعلان في CI. بياناتها fixtures تقنية بلا صور، ولا تحل محل أدلة المتصفح.

استكمال الجولة الثالثة: نجح build للإنتاج لـstaff؛ أُوقف خادم dev وأعيد التشغيل على3001 من ناتج البناء لتقليل كلفة تجميع الصفحات أثناء التصفح. لا تغيير لقاعدة API أو إعداداته. الفحص القادم قرائي مع حظر كل HTTP غير GET/HEAD/OPTIONS باستثناء login/refresh، ولقطات لكل شاشة؛ الحظر إن حدث ليس عيب تطبيق مثبتاً. lint للحزمة الجديدة نجح بعد إعادة تسمية متغير؛ typecheck الممتد إلى test-app كشف ثلاثة أخطاء في المساعد القائم، تسجل ولا تعتبر نجاحاً. لا تعديل مساعد مشترك أو منطق ERP لتجاوزها.

## الجولة الرابعة — 2026-10-22: قيد استمرارية البيئة قبل التنفيذ
