## استراتيجية إعادة الاختبار بعد الاعتماد
1. اختبارات انحدار تكشف كل عيب حالياً قبل الإصلاح على PostgreSQL معزول، لا اختبارات نص مصدر فقط.
2. إصلاح واحد محدود مع قاعدة واضحة؛ بناء/أنواع/Lint واختبارات الوحدة/التكامل ذات الصلة.
3. قاعدة أعمال محلية جديدة، تسجيل خط أساس؛ إعادة MD/PUR/SAL بالأرقام نفسها مع صور قبل الحفظ.
4. مقارنة GL والمخزون والذمم والخزينة وكل التقارير والصادرات، وليس رسالة النجاح فقط.
5. فقط بعد إغلاق عيوب المصدر، استئناف التحصيل والسداد والمردودات والمصاريف والقيود والإقفال والتزامن. يظل كل جزء غير مختبر معلناً.

3. **الترحيل الجماعي للأطراف القديمة** يعتمد على الهجرة وحدها (لا شاشة «إنشاء الحسابات الناقصة»)؛
